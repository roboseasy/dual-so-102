# Pi 분리 구성

팔로워 양팔과 카메라 3대는 라즈베리파이에, 리더 양팔은 PC 에 꽂습니다. Pi 에서 `dual-so102-host` 를 띄우면
로봇이 네트워크에 열리고, PC 의 `lerobot-teleoperate` · `lerobot-record` · `lerobot-replay` · `lerobot-rollout` 은
로봇 타입만 `dual_so102_client` 로 바꾸면 그대로 동작합니다 (LeKiwi 와 같은 방식).

```text
PC (리더 2 + lerobot-*)  <── ZMQ 명령 5555 · 관측 5556 ──>  Pi (dual-so102-host + 팔로워 2 + 카메라 3)
```

## 1. Pi 준비 (새 Pi 만)

로보시지 키트 Pi 는 이미 준비돼 있습니다 (로그인하면 `~/lerobot060_venv` 가 켜짐). 새 Pi 라면:

```bash
sudo apt update && sudo apt install -y python3-venv git v4l-utils
python3 -m venv ~/lerobot060_venv && source ~/lerobot060_venv/bin/activate
pip install torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cpu
mkdir -p ~/workspace && cd ~/workspace && git clone https://github.com/roboseasy/dual-so-102.git && cd dual-so-102
pip install -e .
sudo usermod -aG dialout "$USER"
```

- Python 3.12 이상이 필요합니다 (LeRobot 0.6.0).
- torch 는 CPU 전용 wheel 을 **먼저** 설치합니다. 그래야 Pi 에 쓸모없는 CUDA 패키지가 딸려오지 않습니다.
- 와이파이 · AP 모드 설정은 [dual-so-102_net](https://github.com/roboseasy/dual-so-102_net) 을 씁니다.
- 포트 · 카메라 별칭은 [USB 포트 고정](2.ports.md)을 따릅니다.

## 2. 카메라 확인

```bash
v4l2-ctl --list-devices
v4l2-ctl -d /dev/cam_top --list-formats-ext
```

카메라는 `"fourcc": "MJPG"` 로 엽니다. 무압축(YUYV) 640×480 은 한 대에 약 150 Mbps 라 USB 2.0 에서 두 대째부터
프레임이 끊깁니다. `warmup_s` 는 첫 프레임을 기다리는 시간으로, 기본 1초면 시간 초과가 나는 카메라가 있어 3초로 둡니다.

## 3. host 실행 (Pi)

PC 에서 `ssh` 로 Pi 에 들어가 실행합니다. 첫 실행이면 팔로워 보정을 여기서 합니다 (보정 파일은 Pi 에 저장).

```bash
dual-so102-host \
  --robot.id=bi_so102 \
  --robot.left_arm_config.port=/dev/so102_follower_left \
  --robot.right_arm_config.port=/dev/so102_follower_right \
  --robot.cameras='{"cam_top": {"type": "opencv", "index_or_path": "/dev/cam_top", "width": 640, "height": 480, "fps": 30, "fourcc": "MJPG", "warmup_s": 3}, "cam_left": {"type": "opencv", "index_or_path": "/dev/cam_left", "width": 640, "height": 480, "fps": 30, "fourcc": "MJPG", "warmup_s": 3}, "cam_right": {"type": "opencv", "index_or_path": "/dev/cam_right", "width": 640, "height": 480, "fps": 30, "fourcc": "MJPG", "warmup_s": 3}}'
```

`명령을 기다립니다` 가 찍히면 준비됐습니다. 거울처럼 조종하려면 끝에 `--robot.mirror_mode=true` 를 더합니다
([사용법](1.usage.md) 10절).

```bash
dual-so102-host \
  --robot.id=bi_so102 \
  --robot.left_arm_config.port=/dev/so102_follower_left \
  --robot.right_arm_config.port=/dev/so102_follower_right \
  --robot.mirror_mode=true
```

오래 돌릴 때는 `tmux` 안에서 띄우면 SSH 가 끊겨도 host 가 계속 돕니다 (`nohup dual-so102-host ... &` 도 됩니다).
둘 다 없이 SSH 가 끊기면 host 는 정리(버스 · 카메라 해제, 토크 해제)한 뒤 끝납니다.

## 4. PC 에서 텔레오퍼레이션 · 녹화

```bash
lerobot-teleoperate \
  --robot.type=dual_so102_client \
  --robot.remote_ip=192.168.4.1 \
  --teleop.type=dual_so102_leader \
  --teleop.id=bi_so102_leader \
  --teleop.left_arm_config.port=/dev/so102_leader_left \
  --teleop.right_arm_config.port=/dev/so102_leader_right \
  --display_data=false
```

녹화는 [README](../README.md) 6절처럼 `--robot.cameras` 에 host 와 같은 이름 · 크기를 적습니다. PC 는 카메라를 열지
않으므로 `index_or_path` 는 아무 값이나 됩니다. 텔레옵만 할 때는 카메라 설정을 빼도 됩니다.

| PC ↔ Pi 연결 | `--robot.remote_ip` |
|---|---|
| Pi 의 AP 모드 와이파이(`dualso102-NN`)에 PC 접속 | `192.168.4.1` |
| 유선(PC 의 "다른 컴퓨터와 공유" 연결) | Pi 에서 `hostname -I` 로 확인 (예: `10.42.0.78`) |
| 같은 공유기 | Pi 에서 `hostname -I` 로 확인, `setip <킷 번호>` 로 고정하면 `192.168.0.(100+킷 번호)` |

## 5. 동작 규칙

- **포트**: 명령 5555, 관측 5556. 바꾸면 Pi `--host.port_zmq_cmd` · `--host.port_zmq_observations` 와 PC
  `--robot.port_zmq_cmd` · `--robot.port_zmq_observations` 를 함께 바꿉니다.
- **인증 없음**: 같은 네트워크의 누구나 명령을 보낼 수 있습니다. 폐쇄망에서만 씁니다.
- **client 는 하나만**: 명령을 보내는 PC 가 둘 이상 붙으면(주소를 잘못 친 다른 PC 등) host 가 오류를 남기고
  어느 명령도 따르지 않은 채 자세를 유지합니다. 하나만 남으면 다시 따릅니다.
- **끝내기**: PC 를 끝내도 팔은 마지막 자세를 유지합니다. 토크 해제는 host 를 끝낼 때(Ctrl+C · `kill` ·
  SSH 끊김) 일어나므로 팔을 받칩니다.
- **명령 끊김(watchdog)**: 명령이 0.5초(`--host.watchdog_timeout_ms`) 넘게 오지 않으면 host 가 경고를 한 번 남기고
  새 목표를 쓰지 않습니다 (마지막 자세 유지). 명령이 다시 오면 이어 갑니다.
- **관측 끊김**: host 관측이 1초(`--robot.stale_timeout_s`) 넘게 오지 않으면 PC 가 오류로 멈춥니다. 멈춘 host 의
  오래된 프레임이 데이터셋에 들어가거나, 응답 없는 host 에 명령만 보내지 않게 하려는 것입니다. 녹화 중 에피소드
  저장처럼 PC 루프만 멈춘 것은 괜찮습니다.
- **카메라**: 연결할 때 PC 설정의 카메라가 모두 오는지, 크기가 같은지 확인하고 다르면 바로 알려 줍니다. Pi 에서
  카메라 프레임이 늦거나 카메라가 빠지면 host 는 그 카메라만 빈 프레임으로 보내고 계속 돕니다 (팔은 자세 유지). PC 는 한두 장
  빠진 프레임을 직전 프레임으로 메우고 (검은 화면을 만들지 않음), 한 카메라가 1초 넘게 안 오면 멈춥니다.
- **모터 버스 순간 끊김**: 읽기 · 쓰기마다 2번 더 시도하고, 그래도 실패한 관측은 그 주기만 건너뜁니다. 연속 5번이면
  host 가 오류를 남기고 정리한 뒤 끝납니다 (케이블 분리 · 전원 차단).
- **대역폭**: 카메라 3대 640×480 30 fps 는 약 40 Mbps 입니다. 유선이나 5 GHz 와이파이를 권합니다. 끊기면
  `--host.jpeg_quality=60` 이나 `--host.max_loop_freq_hz=15` 로 줄입니다.

## 6. 기존 host 와 함께

키트 Pi 에는 기존 양팔 코드의 host(`python -m lerobot.robots.bi_so102_follower.bi_so102_host`)도 그대로 있습니다.
전송 형식이 같아 기존 host 에 새 client(`dual_so102_client`)가 붙습니다. 다만 두 host 를 동시에 띄울 수는 없습니다 —
새 host 는 포트가 이미 쓰이면 팔을 건드리기 전에 `포트 5555 사용 중` 오류로 멈춥니다. 기존 host 를 먼저 끕니다.
