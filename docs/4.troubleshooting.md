# 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `invalid choice: 'dual_so102_follower'` | 이 패키지가 그 환경에 없음 | 그 환경을 켜고 `pip install -e .`, `pip show lerobot_robot_dual_so102` 로 확인 |
| `--robot.id 를 지정하세요` | id 없이 실행 | `--robot.id=bi_so102` (리더는 `--teleop.id=bi_so102_leader`) |
| `포트 5555 사용 중 — 다른 host ... 를 먼저 끄세요` | 기존 host 나 다른 `dual-so102-host` 가 돌고 있음 | `ss -ltnp \| grep 555` 로 찾아 끈 뒤 다시 실행 (팔은 건드리지 않았습니다) |
| `... 의 dual-so102-host 응답이 없습니다` | Pi 에서 host 가 안 돎 · 아직 카메라를 여는 중(약 16초), IP · 포트가 다름, 방화벽 | host 로그 확인, Pi 에서 `hostname -I`, `--robot.remote_ip` 확인 |
| `host 가 카메라 [...] 를 보내지 않습니다` | PC 와 host 의 카메라 이름이 다름, host 명령의 카메라 줄 누락 | 두 쪽 `--robot.cameras` 이름을 같게, host 명령 줄 끝 `\` 확인 |
| `카메라 cam_top: host (240, 320, 3) != 설정 (480, 640, 3)` | 카메라 크기가 다름 | PC `--robot.cameras` 의 width · height 를 host 와 같게 |
| `host 관측이 N초째 오지 않습니다` | host 가 멈춤 · 끝남, 네트워크 끊김 | Pi host 로그 확인. 녹화는 거기서 멈추므로 다시 시작 |
| `카메라 cam_left 프레임이 N초째 오지 않습니다` | Pi 에서 그 카메라가 빠짐 · 끊김 (host 로그: `카메라 cam_left 를 읽지 못해 빈 프레임으로 보냅니다`) | 카메라 USB · 별칭(`ls -l /dev/cam_*`) 확인. 늦었던 것이면 프레임이 다시 오는 대로 host 가 이어 가고, USB 가 빠졌던 카메라는 다시 꽂은 뒤 host 를 다시 띄웁니다 (팔을 받친 채). Pi 커널 로그 `journalctl -k \| grep usb` 에 `error -71` 이 보이면 케이블 · 허브 전원을 봅니다 |
| host 로그 `명령 client 가 2개 붙었습니다` | PC 두 대가 같은 Pi 에 붙음 (주소를 잘못 침), 와이파이가 끊겼다 다시 붙음 | 한 PC 의 명령을 끕니다. 와이파이 재접속이면 몇 초 뒤 저절로 풀립니다 |
| host 의 `관측 읽기 실패 (n/5)` 경고 | 모터 버스 순간 무응답 (전류 피크 · USB 경합 · 발열) | 어댑터 전류 여유, 카메라와 시리얼 허브 분산, Pi 는 `vcgencmd get_throttled` |
| 연결할 때 `Failed to write 'Torque_Enable' ... Incorrect status packet` 으로 끝남 | 모터 버스 순간 통신 오류 (레지스터 쓰기는 2번 더 시도한 뒤의 오류) | 팔을 받친 채 다시 실행. 계속 나면 12 V · 5 V 어댑터와 데이지 체인 커넥터, `dual-so102-check` 확인 |
| host 가 `관측 읽기가 5번 연속 실패` 로 끝남 | 케이블 분리 · 팔로워 12 V 전원 꺼짐 | 전원 · 데이지 체인 확인, `dual-so102-check` |
| `Timed out waiting for frame from camera` | USB 대역폭 부족(무압축) 또는 첫 프레임 지연 | 카메라 설정에 `"fourcc": "MJPG", "warmup_s": 3`, 카메라를 여러 USB 포트에 나눔 |
| `dual-so102-check` 가 `모터 응답 없음` | 그 보드의 서보 전원이 꺼짐 · 케이블 빠짐 | 리더 5 V · 팔로워 12 V 어댑터, 보드와 첫 모터 사이 케이블 |
| `dual-so102-check` 가 `빠진 ID x` · `남는 ID y` | 모터 ID 를 아직 안 썼거나 잘못 씀 | `dual-so102-setup-motors` 로 그 팔을 다시 설정 |
| `dual-so102-check` 가 `사용 중 (pid N)` | host · 텔레옵 · 녹화가 그 포트를 쓰는 중 | 그 프로그램을 끄고 다시 (쓰는 중인 포트를 같이 열면 그 프로그램이 끝나 토크가 풀리므로 열지 않습니다) |
| `dual-so102-check` 가 `열 수 없음` | 포트 권한 없음, 포트가 사라짐 | `dialout` 그룹, USB 를 다시 꽂고 `ls -l /dev/ttyACM*` |
| 텔레옵 반응이 둔하고 팔로워가 늦게 따라옴 | `--robot.left_arm_config.max_relative_target` · `--robot.right_arm_config.max_relative_target` 을 줌 | 옵션을 뺌 (관절 속도 상한 + 명령마다 추가 읽기) |
| 팔이 좌우 엇갈려 움직임 | 포트 별칭의 좌우가 바뀜, 또는 미러 모드 | `dual-so102-check` · 한 팔씩 뽑아 별칭 확인, `Mirror mode` 로그 확인 |
| `--resume` 이 robot_type 이 달라 거부됨 | `dual_so102_*` 와 다른 타입(기존 `bi_so102_*` 포함)으로 만든 데이터셋 | 새 데이터셋으로 녹화 (학습 · 추론은 키가 같아 영향 없음) |
| 기존 정책 추론에서 카메라 키가 안 맞음 | 기존 양팔 코드 데이터셋은 카메라 이름이 `cam_wrist_left` · `cam_wrist_right` | 같은 이름으로 `--robot.cameras` 를 주거나 `--rename_map` 사용 |
| 여러 줄 명령의 뒷부분이 무시됨 | 줄 끝 `\` 뒤에 공백이 있거나 `\` 가 빠짐 | 각 줄이 `\` 로 끝나는지 확인 |

## LeRobot 을 덮어쓴 환경

기존 양팔 코드의 `solution/` 을 LeRobot 소스에 덮어쓴 환경인지 확인합니다.

```bash
python -c "import lerobot.robots.so102_follower" && echo "덮어쓴 LeRobot"
```

- 이 패키지는 `dual_so102_*` 만 등록하므로 덮어쓴 LeRobot 에서도 동작합니다 (키트 Pi 가 이 상태입니다).
- 단팔 `so-102` 플러그인은 `so102_follower` 를 등록하므로 덮어쓴 LeRobot 과 같이 쓸 수 없습니다. 둘 다 쓰려면
  LeRobot 0.6.0 을 깨끗하게 다시 설치합니다.
